# Плейлист-вопрос `vetka.cut.question_playlist/1`

Агент отдаёт одним файлом «вот N мест для проверки»: запись = ссылка на файл
+ вопрос + гипотеза + скобки in/out + маркеры-подсказки. Пользователь отвечает
ответом на маркер вопроса — кнопкой карточки или ↳ (favorite = угадал,
negative = нет, comment = спорно / свободный текст). Ответы живут в маркерах;
`<playlist>.answers.json` рядом с плейлистом — их выжимка, плеер пересобирает
её при каждом ответе (0.25.55) — агент читает её без плеера. Все поля необязательные: старый плейлист без них открывается как раньше.

**Время — секунды от начала файла, не таймкод.** `question_id` — локальный ключ
плейлиста; `ref` — ключ базы, по нему агент пишет ответ обратно
(`confirmed` / `rejected` + `confirmed_by`).

```json
{
  "schema": "vetka.cut.question_playlist/1",
  "source": { "by": "agent", "task": "tb_1791521998_11250_5", "layer": "camera" },
  "id": "camera-calibration",
  "name": "Калибровка камеры",
  "entries": [
    {
      "path": "/idx/P1755050.mov",
      "name": "P1755050.mov",
      "duration": 3420,
      "question_id": "cam-q03",
      "question": "План общий?",
      "hypothesis": "FS, камера A",
      "in_sec": 12.5,
      "out_sec": 18.0,
      "bbox": { "x": 0.31, "y": 0.22, "w": 0.18, "h": 0.24 },
      "bbox_end": { "x": 0.33, "y": 0.23, "w": 0.18, "h": 0.24 },
      "markers": [{ "kind": "comment", "t_sec": 14.0, "text": "граница плана" }],
      "ref": { "layer": "camera", "id": "shot-7" },
      "choices": ["pan", "truck", "dolly", "zoom", "hold"]
    }
  ]
}
```

`bbox` — регион-лицо в долях кадра (плеер рисует рамку, пока активен
вопрос; `bbox_end` — рамка на `out_sec`, плеер едет между ними за
`in..out`). `label` (имя маркера) держать ≤ 80 символов.

Ответ (`<playlist>.answers.json`, объект `{ "answers": [...] }`):

```json
{ "answers": [
  {
    "question_id": "cam-q03",
    "verdict": "favorite",
    "choice": "pan",
    "comment": "сошлось",
    "t_sec": 15.2,
    "in_sec": 12.5,
    "out_sec": 18.0,
    "confirmed_by": "operator",
    "answered_at": "2026-10-09T05:00:00.000Z"
  }
] }
```

Правила:

- `verdict` ∈ `favorite` | `negative` | `comment` (карточка: Confirm / Reject /
  Not sure; свободный текст ↳ на вопрос — `comment`). `choice` — только если у записи
  есть `choices`: с 0.26.7 варианты и есть кнопки ответа, `choice` пишется ВСЕГДА
  (см. «Карточка: один ряд ответов» ниже). `confirmed_by` — автор ответа,
  по умолчанию `"operator"`; автор вопроса (`agent:<роль>`) не подставляется.
- **Одна правда — маркеры** (решение 12.10, 0.25.55): файл ответов — производный,
  выжимка `answersFromMarkers`; руками и агентом его не дописывают. Поля берутся
  из маркеров: `t_sec` — точка ответа, `answered_at` — время создания ответа,
  `in_sec` / `out_sec` — текущие скобки вопроса. Маркер вопроса несёт `question_id`.
  В выжимку идут только прямые ответы на маркер вопроса `qmat_*`; ответы на ответы —
  просто комментарии. Несколько ответов на один `question_id` допустимы, действует
  последний по `answered_at`.
- ★/✗ с родителем (reply на `qmat_*`) — это ОТВЕТ, а не отбор (Commander 12.10):
  отборы оператора — только favorite/negative БЕЗ родителя.
- Поведение плеера: импорт файла в панели Playlist СРАЗУ пишет скобки
  штатными маркерами (in/out-пары + комменты `agent:<роль>`, повторный импорт
  без дублей) — кнопок нет. Клик по записи открывает файл и ведёт к `in_sec`.
  Импорт везёт видео с собой 0.25.67 (`lib/markersImport.ts`: один distinct
  path — открываем, несколько — не гадаем; привязка SOS `media_path`).
  Дедуп импорта 0.25.69 — по паре id+медиа (`markerDedupKey`): повтор того же
  файла режется, тот же вопрос на другом видео — новые маркеры.
  [task:tb_1791864876_84020_4]
  Окно Markers (ex-Comments): kind-фильтр, ответы кнопкой ↳, новый коммент
  полем + Save. Экспорт Playlist → XML: подрезанные клипы с комментариями
  (манифест §5). Путь открывается как есть, без подмен (прокси ≠ исходник —
  смотри точный `path`).
- Пример: `e2e/fixtures/question-playlist-camera.json` (3 записи).

## Какому вопросу уходит ответ (0.26.6, [task:tb_1793480340_10647_1])

Живой прогон фото-капчи 31.10: один mp4 на 6 слайдов, вопросы на трёх из них;
оператор смотрел всё видео, и ответы со слайдов без вопроса легли на чужие
вопросы (один вердикт перевёрнут). Правила плеера теперь такие:

- **Ответ принимается только внутри скобок вопроса карточки** (`in_sec ≤ t ≤
  out_sec`, `t` — позиция плейхеда). Вне скобок весь ряд кнопок ответа (Confirm /
  Reject / Not sure или варианты `choices`) неактивен, карточка пишет «Playhead
  is outside this question».
- Плейхед вошёл в скобки ДРУГОГО вопроса того же файла и плейлиста — карточка
  переключается на него. На общей границе двух окон (0–10 и 10–20, `t = 10`)
  текущий вопрос остаётся своим, дальше выигрывает окно, которое начинается.
  Набранный комментарий не теряется: карточка остаётся, но отвечать ей с чужой
  позиции нельзя.
- **Запись без `in_sec` / `out_sec` — вопрос на весь файл** (картинка, короткий
  клип): карточка показывается и на картинке, ответ крепится к маркеру
  `qmat_<question_id>_whole` (комментарий в 0:00 с текстом вопроса), в ответе
  `in_sec` / `out_sec` нет. «Один вопрос = одна картинка» — штатный режим.
- `in_sec` / `out_sec` в ответе — текущие скобки вопроса (`out_sec` берётся из
  маркера `out`, не из точки `in`). Одинокий IN: `out_sec` в ответе не пишется.
- Ножницы (In–Out Play, клавиша S): дойдя до OUT последней записи плейлиста,
  плеер встаёт на паузу на скобке; **play оттуда начинает плейлист заново**
  (первая запись), а не уходит в щель за скобками.

Как составлять плейлист агенту:

- Скобки одного файла в одном плейлисте не пересекаются, и каждое место, где
  ждут ответ, покрыто скобкой. Нужно ответить на все слайды — дайте вопрос на
  каждый слайд. Вопросов не больше, чем просил оператор: лимит задаёт он, а не
  формат.
- Несколько вопросов на одном видео (сначала камера, потом сцены) — законный
  сценарий: либо один плейлист с непересекающимися скобками, либо плейлисты
  один за другим. Ответы каждого плейлиста лежат в своём `answers.json`.
- Для стоп-кадров и слайдов проще всего **один файл на вопрос** (картинка без
  скобок): номер вопроса, который видит оператор, совпадает с номером в очереди.
  **Заголовок, вопрос и варианты ответа в картинку не вшивать** (слово оператора
  01.11): пилюля плеера с иконками неподвижна и лежит поверх верха кадра
  (двигается только карточка вопроса), вшитый заголовок оказывается под ней и
  режется; текст на слайде — работа генератора. Вопрос — в `question`, варианты — в `choices`
  (карточка показывает их сама), подпись к кадру — `caption`.
  Плеер на нескольких вопросах одного файла показывает «Question N/M on this
  file» — это номер внутри файла; номер очереди пишите в `question` /
  `name` записи.

## Карточка: один ряд ответов (0.26.7, [task:tb_1793558199_43420_2])

Живая работа 01.11: в карточке было два ряда — варианты `choices` сверху и
Confirm / Reject / Not sure снизу. Вариант сам ничего не писал (чип только
подсвечивался), ответ писал нижний ряд, и оператор забывал нажать «и там, и
там». Теперь ряд один:

- **У записи есть `choices`** — карточка рисует только их, клик по варианту =
  сразу ответ (`verdict` + `choice`). Подписи `confirm` / `reject` / `not_sure`
  показываются как Confirm / Reject / Not sure, остальные — как в `choices`
  (`master`, `model`, `other`, `student` …). Пустые, повторные и не-строки в
  `choices` отбрасываются.
- **`choices` нет** — три кнопки Confirm / Reject / Not sure, как раньше.
- **`verdict` варианта:** `confirm` → `favorite`, `reject` → `negative`,
  `not_sure` → `comment`, любой другой вариант → `favorite` («ответ дан»).
- **`choice` пишется всегда**, если ответили вариантом, в том числе у да/нет-
  вопроса (`confirm` / `reject` / `not_sure`). Раньше у да/нет-вопроса `choice`
  обычно не было.
- Комментарий печатается до клика и уходит вместе с ним. Вне скобок вопроса и
  без маркеров гаснет весь ряд.
- Текст вопроса в карточке переносится на несколько строк (до четырёх), а не
  режется в одну.

Формат `answers.json` и reply-маркера (`[answer] choice: comment (verdict)`)
не менялся — читающему агенту переделывать нечего.

**Маркеры вопроса не теряются и лечатся сами (0.26.8, [task:tb_1793567711_43420_2]).**
В 0.26.7 открытие плейлиста через меню или очередь агента могло потерять только
что созданные `qmat_*` (ack говорил `materialized: 35`, а в хранилище маркеров их
не было): окно плеера получало собственное событие `markers:changed` раньше, чем
успевало записать маркеры, и стирало их — карточка гасла плашкой «No question
markers… Reimport the playlist». Теперь маркеры пишутся в хранилище до события, а
если вопрос карточки есть в загруженном плейлисте без маркеров, плеер один раз
материализует плейлист заново (тост «Restored N question markers») — переимпорт
не нужен. Агенту: `materialized` в ack — число созданных маркеров, а не гарантия
того, что оператор может ответить; проверять ответы надо по `answers.json`.

**«Send to agent» сохраняет набранный комментарий (0.26.9, [task:tb_1793586334_43420_1]).**
До 0.26.9 кнопка только копировала готовый `answers.json` в `ack/` и не читала поле
Comment; при смене слайда поле очищалось. Оператор жал её как «сохранить» в случаях,
когда ни один вариант не подходил, и текст пропадал (плейлист `r2`, 02.11: 16 вопросов
из 44 без единой записи, восстановить нельзя). Теперь, если в поле есть текст, кнопка
сначала записывает его ответом на вопрос карточки — `verdict: "comment"`, `choice`
нет, тот же путь, что у «Not sure» (reply-маркер и `answers.json`), — и только после
успешной записи шлёт `ack/<cmd>.answers.json` (`"sent_by": "operator"`) уже с этим
ответом. Пустое поле — как раньше, уходит только ack. Не записалось (нет пути
плейлиста, плейхед вне скобок вопроса) — ack не уходит, тост говорит почему, текст
остаётся в поле. Агенту: «ни один вариант не подходит» приходит как запись
`verdict: "comment"` без `choice`, текст в `comment`; такой вопрос отвечен, но без
выбора из списка.

В окне Markers ответ-вариант (`student`, `other` …) больше не рисуется со звездой и
припиской `(favorite)`: такого варианта у вопроса нет, `favorite` для него лишь
технический вердикт «ответ дан». Это только отображение: тип маркера, текст
`[answer] choice: comment (favorite)` и `answers.json` не менялись. Для вариантов
`confirm` / `reject` и для кнопок Confirm / Reject звезда и крест остаются.

**Всё, что оператор отметил, доходит до агента через `answers.json` (0.26.10,
[task:tb_1794347727_83767_1]).** Оператор отвечает не только кнопками карточки: во
время просмотра он ставит на плейхед СВОИ маркеры — ★, ✗ или комментарий (кнопки
пилюли, `F` / `N` / `M`, окно Comments). До 0.26.10 такие маркеры в `answers.json`
не попадали: он нёс только ответы на маркеры агента, а свои заметки оператора
лежали в `<видео>.sos.json` (живой кейс `queue_reelsD-201336`, 11.11: свой negative
и два комментария оператора агент не увидел, запись `ig_D` висела в
`pending_question_ids`). Контракт теперь такой: **`answers.json` — единственное
место, откуда агент берёт всё, что оператор сказал по вопросам плейлиста;
`.sos.json` — собственный sidecar плеера, за ответами в него ходить не надо.**

Что считается СВОИМ маркером оператора внутри записи:

- ★ / ✗ / 💬 (`favorite` / `negative` / `comment`) без `reply_to`, не от агента
  (`author` не `agent:…`), не `qmat_*`; комментарий без текста не берётся.
- Стоит на файле записи (тот же `media_path`, что у маркеров вопроса), а `t_sec`
  внутри скобок вопроса — по ТЕКУЩИМ `in`/`out` (человек мог сдвинуть qmat).
  Общая граница двух окон (`out` одного = `in` другого) отдаётся окну, которое
  начинается; вопрос без скобок (картинка, весь файл) берёт любой такой маркер
  файла. Вне скобок — не ответ.
- Поставлен после того, как вопрос был задан: заметки прошлого прогона на том же
  файле (например, `r2`) новому вопросу не приписываются.

Запись в `answers` выглядит как обычный ответ плюс признак происхождения:

```json
{ "question_id": "ig_D", "verdict": "negative", "t_sec": 15.97,
  "marker_start_sec": 15.47, "marker_end_sec": 16.47,
  "confirmed_by": "danilagulin", "answered_at": "2026-11-10T21:47:05.392Z",
  "origin": "operator_marker", "marker_id": "marker_mwb80c34_u56426" }
{ "question_id": "ig_D", "verdict": "comment", "t_sec": 15.97,
  "comment": "Не та версия, сделал новую /Volumes/…/Igor_D-cut06-5_nocolor_422_25.mov",
  "confirmed_by": "danilagulin", "answered_at": "2026-11-10T21:47:31.544Z",
  "origin": "operator_marker", "marker_id": "comment_mwb80w9k_7luk" }
```

- `verdict` = вид маркера, `comment` = его текст (у ★/✗ без текста поля нет),
  `t_sec` = позиция на файле, `marker_start_sec` / `marker_end_sec` — только у
  маркера-диапазона. `choice` у такой записи нет никогда. `origin:
  "operator_marker"` отличает её от ответа карточки (у того `origin` нет);
  `marker_id` — id маркера в плеере. У comment-маркеров нет `created_at`, поэтому
  `answered_at` берётся из id маркера (`comment_<base36 от Date.now()>_…`).
- Такой маркер **считается ответом на вопрос**: запись уходит из
  `pending_question_ids` в `answered_question_ids`, `complete` считается с учётом
  этих записей. Это заметка о конкретном месте, а не обязательно ответ «да/нет» на
  сам вопрос: читать надо `comment` и `t_sec`, `negative` без текста значит «здесь
  плохо».
- Записи оператора зеркалят его маркеры: правка текста заменяет запись, удалённый
  маркер уходит из файла при следующей записи. Если маркеров вопроса в хранилище
  плеера нет (хранилище не загрузилось, другая машина), записи оператора в файле
  остаются как были. Ответы карточки по-прежнему только дописываются.
- Когда пишется: при каждом ответе карточки и при нажатии **Send to agent** —
  кнопка перед ack пересобирает `answers.json` из всех маркеров и работает, даже
  когда кнопок карточки не нажато ни разу. Тост показывает, сколько своих
  маркеров ушло: «Sent to agent (incl. 3 own markers)». Сам по себе маркер в
  файл мгновенно не попадает — только при следующей записи.
- Не переносятся: `in` / `out` / `chat` оператора (навигация и скобки ножниц, не
  вердикт), ответы-треды на его маркеры и маркеры вне скобок вопросов.

**Как читать ответы.** У вопроса вида «Кто это?» (`master` / `model` / `other` /
`student`) содержание ответа — `choice`; `verdict` лишь отличает «назвали»
(`favorite`) от «не уверен» (`comment`). Ответ на такой вопрос БЕЗ `choice`,
записанный старой карточкой (до 0.26.7 нажат только нижний Confirm), — это «нет
данных», а не `other`.

## Судьба полей (решение 09.10 — пересмотрено 10.10 дважды, [task:tb_1791654032_27281_1])

Схема не переписывается, но эфемерных скобок больше нет: импорт пишет
`in_sec` / `out_sec` / `markers` записи СРАЗУ штатными маркерами с автором
agent:<роль> (манифест §5). Пунктир, скип-движок и кнопка «Материализовать»
(0.25.33) удалены. Обратный канал (`answers.json`, `confirmed_by`) с 0.25.55 —
выжимка из маркеров-ответов (см. «Правила»).
