## (1) Автор комментария — ДЁШЕВО (S, одна посадка)

Поля (все опциональные, старые файлы читаются как раньше):

- Модель: заполнять `author` по контексту (руками оператор / импорт из
  SRT-sidecar агента) вместо хардкода. ~5 строк.
- SRT-транспорт: 3-й сегмент `· label | author | text` (сейчас
  `splitMarkerPrefixLine` делит всё после первого `|` на label|text).
  Писать сегмент только когда author не пуст; парсер: 2 сегмента = как
  сейчас, 3 сегмента = с автором. ~25 строк + тесты.
- Sidecar/Markers JSON: опциональное `author` в `SidecarMarker` и
  `normalizeImportedMarker` (лишнее и так отбрасывается). ~10 строк.
- Показ: одна строка «автор» в карточке CommentOverlay. ~15 строк.
- XML: автор в имя маркера (`reviewMarkerName`: `★ label — author`) —
  виден в Premiere штатно, схема XMEML не меняется. ~10 строк.
- EDL: автор в note (`sanitizeEdlNote`). ~5 строк. Честно: EDL строго
  ASCII (0.24.1) — кириллический автор в DaVinci не доедет, только латиница.
- Совместимость: старые SRT/JSON/XML читаются (дефолт `""` = показ как
  сейчас, без автора). Новые файлы старый плеер тоже читает (лишний
  сегмент/поле игнорируется, автор просто не показывается).

Итого: ~70–120 строк кода + ~40 тесты. В лимит ≤10 МБ влезает (байты, не
мегабайты). Вердикт: делать в Mark Player.

Прицепом (тем же заходом, +~20 строк): статус «сделано» — сейчас
`status: "active"` литерал; расширить union + бейдж/фильтр в Comments.
Без этого правки по протоколу §11 нечем отмечать.

## (2) Reply-ветка — СРЕДНЕ (M, 2–3 посадки или одна большая)

Модели нет, делать с нуля:

- Модель: `parent_id?: marker_id` (или оживить `comment_thread_id`) +
  миграция LS-хранилища (старые маркеры без поля = корни). ~30 строк.
- UI Comments: группировка ветки, отступ, кнопка Reply, создание дочернего
  коммента в той же точке. ~120–180 строк (самый крупный кусок).
- SRT: reply — отдельный cue со ссылкой на родителя (формат придумать;
  старый плеер прочтёт его как обычный коммент — обратно совместимо).
  ~30 строк.
- Sidecar: поле `reply_to`. ~10 строк.
- XML/EDL: reply отдельным маркером `[reply] …` или склейка в текст
  родителя (решить при реализации; Premiere вложенности не умеет —
  только плоский список). ~30 строк.
- Тесты: модель + парсинг + группировка. ~80 строк.

Итого: ~300–450 строк. Вердикт: по условию оператора «только если дёшево» —
НЕ дёшево. Варианты: (а) отложить до CUT player; (б) урезать до «ответ
текстом дописывается в тот же комментарий» без ветки (S, ~30 строк:
append к `text` + автор строкой) — покрывает «агент спрашивает, человек
отвечает в том же месте» без дерева.
