# Манифест данных Mark Player для агента

Как агенту без GUI, одними файлами, положить ШТАТНЫЕ маркеры плеера
(in/out, комментарии) для видео — чтобы их увидели и плеер, и Premiere.

Протокол: этапы 6, 7, 11 — `docs/218_ph_CUT_CATALOG/CUT_PRODUCTION_PROTOCOL_2026-10-09.md`.
Живой манифест кнопок: `window.vetkaPlayerLab.manifest()` в запущенном плеере.

**Правило №1.** Агент сначала ищет готовый инструмент в этом документе.
Новый формат — только через Альфу: новое поле должны увидеть и плеер,
и Premiere (протокол §4 п.1).

## 0. Что такое штатные маркеры

Виды: `favorite` (★), `negative` (✗), `in` (⇒), `out` (←),
`comment` (·), `chat` (·). Пара `in` + `out` = скобки фрагмента, их сумму
считает плеер. Время — СЕКУНДЫ от начала файла (в SRT — `HH:MM:SS,mmm`).

Честно: плеер НЕ подбирает файлы-спутники сам при открытии видео.
Импорт — явный: меню File → Import или вызов `window.vetkaPlayerLab`
(см. §3). Файл, просто лежащий рядом с видео, маркеров не даст.

## 1. Путь А: SRT-файл маркеров (самый простой)

Формат — тот же, что пишет сам плеер (Export → Current Video →
Subtitles (SRT)…): номер, время, строка `ГЛИФ label | text`.

```srt
1
00:00:12,500 --> 00:00:12,500
⇒ заминка 3

2
00:00:14,000 --> 00:00:18,000
· спорное место | проверить по расшифровке

3
00:00:18,000 --> 00:00:18,000
← заминка 3
```

Глифы: `★ favorite`, `✗ negative`, `⇒ in`, `← out`, `· comment/chat`.
Точечный маркер — нулевая длительность (`start == end`).
Импорт: File → Import → Subtitles (SRT)… (или
`vetkaPlayerLab.importSubtitlesText(text, mediaPath)`), затем подтвердить
«создать маркеры». Эвристика плеера: если ≥50% строк начинаются с глифа —
это SRT маркеров, а не субтитры (`looksLikeMarkers`). Кодировка: UTF-8,
иначе cp1251. Повторный импорт заменяет дорожку целиком.

## 2. Путь Б: Markers JSON / sidecar `.sos.json`

Sidecar (`sos_version: "0.3"`, пишет Export → Markers (JSON/SOS)…):

```json
{
  "sos_version": "0.3",
  "source": "cut_player",
  "media_path": "/idx/P1755050.mov",
  "content_hash": null,
  "generated_at": "2026-10-09T00:00:00.000Z",
  "markers": [
    { "marker_id": "q03-in", "kind": "in", "start_sec": 12.5,
      "end_sec": 12.5, "anchor_sec": 12.5, "label": "заминка 3", "text": "" },
    { "marker_id": "q03-c1", "kind": "comment", "start_sec": 14.0,
      "end_sec": 18.0, "anchor_sec": 16.0, "label": "спорное место",
      "text": "проверить по расшифровке" }
  ],
  "provisional_events": []
}
```

Импорт принимает и короткий массив `[{kind, text|label, anchor_sec|time,
start_sec, end_sec}]` — лишнее отбрасывается, неизвестный `kind` становится
`favorite` (`normalizeImportedMarker`). Импорт: File → Import →
Markers (JSON)…. Привязка к видео — по `media_path` (копия/переименование
находится по `content_hash`, `null` = хеш неизвестен, честно).

## 3. Как плеер подхватит (без GUI — никак, нужен один шаг человека или API)

Варианты: (а) оператор открывает видео и жмёт File → Import → …;
(б) агент в десктопе вызывает `vetkaPlayerLab.importSubtitlesText(text,
mediaPath)` — `mediaPath` обязан совпадать с открытым файлом, иначе тост
«open a video first». После импорта маркеры — штатные: видны на шкале,
в окне Comments, едут в экспорт.

## 4. Как маркеры уходят в Premiere

- Timeline (XML)… — маркеры файла с цветами видов (comment/note/chat —
  синий, favorite — зелёный, negative — красный; ABGR, проверено глазами
  в Premiere 24.09). Частота кадров — честная (`resolveXmlFps`:
  container/probe/estimated/fallback — сверить настройки сиквенса).
- Markers (EDL, DaVinci)… — для DaVinci.
- Для плейлиста — те же пункты в Export → Playlist (пакет:
  XML + SRT + JSON + Review Notes + frames + `.editor/`).
- Сырые скобки вопроса (§5) в Premiere не уходят; штатные маркеры,
  записанные при импорте вопрос-плейлиста, уходят как обычно.

## 5. Плейлист-вопрос: импорт сразу пишет штатные маркеры (решение 10.10, работает с 0.25.34, [task:tb_1791654032_27281_1])

Агент отдаёт ОДИН JSON на все видео (`vetka.cut.question_playlist/1` —
схема в `QUESTION_PLAYLIST.md`): запись = путь + `question_id` + вопрос +
гипотеза + `in_sec`/`out_sec` + `markers`. Человек открывает файл в панели
Playlist — скобки записей СРАЗУ становятся штатными маркерами, без кнопок
и подтверждений (файл агента и есть подтверждение). `source.by` — имя
агента (станет автором `agent:<имя>`); без него автор — `agent:agent`:

- `in_sec` / `out_sec` → пара `in` + `out` (в XML режут клипы, как ручные I/O);
- `markers` записи → комменты (`label` = вопрос, `text` = гипотеза + текст);
- автор всех — `agent:<роль>` из `source.by` (это и есть пометка «ИИ»);
- повторный импорт дублей не плодит (детерминированные id `qmat_<qid>_*`).

Эфемерных скобок больше нет: пунктира, скип-движка и кнопки
«Материализовать» (0.25.33) — тоже. Дальше всё штатно: окно Markers,
ответы кнопкой ↳, Export → Playlist → XML (подрезанные клипы
с комментариями в Premiere).

Правило резолва путей: плеер открывает `entry.path` как есть, без подмен
(прокси не конформит в исходник и наоборот). Коллизия имён (у прокси
и исходников одинаковые basenames) — на совести агента: клади точный путь.

Две «скобки» (не путать):

1. In–Out Play (ножницы) — РЕЖИМ просмотра: играть только внутри скобок.
2. Штатные `in` / `out` (⇒/← — ставит человек клавишами I/O или агент
   в SRT) — ДАННЫЕ: в XML становятся разрезами клипов.

## 5.1. Калибровка сцен для Беты (решение 11.10): новый плейлист штатными инструментами

Старые `camera_calibration.json` / `scene_proposals.json` — не плейлисты,
больше не отдавать (плеер 0.25.45 ел их transitional-мостом — мост остаётся
для чтения, новым форматом не является). Новый лист калибровки сцен —
обычный вопрос-плейлист §5 (`vetka.cut.question_playlist/1`), собранный
только штатными средствами:

- запись = файл; `in_sec` / `out_sec` — штатные скобки (I/O или числа —
  в XML режут как ручные);
- ВСЕ вопросы — в поле `question` + штатными комментариями (`markers`
  записи: `label` = вопрос, `text` = гипотеза); survey-форматов не лепить —
  запрещено. Разрешённые штатные поля (с 0.25.52): `bbox` / `bbox_end` (см.
  ниже) и `label` ≤ 80 символов (длиннее плеер режет сам; имя маркера
  в Premiere обрезается на полуслове — держи коротким);
- регион-лицо: `bbox: {x, y, w, h}` в ДОЛЯХ кадра (x,y — левый верхний
  угол; всё 0..1, x+w ≤ 1, y+h ≤ 1), опционально `bbox_end` — рамка на
  `out_sec`. Канон — поля ЗАПИСИ; `bbox` внутри `markers[i]` tolerated
  (плеер подхватит из первого маркера, где есть — так лёг people_merges_v01).
  Плеер рисует рамку поверх кадра, пока активен вопрос, и
  линейно едет `bbox` → `bbox_end` за `in..out` (на тугих скобках выглядит
  как трекинг). Мусор (вне 0..1, нулевой размер, вылезание за кадр)
  отбрасывается целиком — лучше без рамки, чем мимо лица. Честно:
  в Premiere рамка уезжает ТЕКСТОМ (`[region …]` в тексте in/out-маркера —
  в XMEML/EDL/SRT полей под геометрию нет);
- вопросы и ответы живут в окне Comments. **Одна правда — маркеры**
  (решение 12.10, плеер 0.25.55, [task:tb_1791809796_24701_1]): ответ
  человека — reply-маркер на маркер вопроса `qmat_*` (кнопка карточки
  Confirm / Reject / Not sure пишет `[answer] choice: comment (verdict)`,
  свободный текст ↳ — тоже ответ, verdict `comment`). `answers.json` —
  НЕ второй писатель, а выжимка `answersFromMarkers` из маркеров: плеер
  пересобирает её при каждом ответе (имя — от пути плейлиста; без пути —
  запасной аутбокс). Поля выжимки берутся из маркеров: `t_sec` = точка
  ответа, `answered_at` = время создания ответа, `in_sec`/`out_sec` =
  текущие скобки вопроса (человек двигает их сам). Маркер вопроса несёт
  `question_id` полем. В выжимку идут только прямые ответы на `qmat_*`;
  треды на обычных маркерах — просто комментарии. Автор ответа на вопрос
  агента — отвечающий; автор вопроса (`agent:<роль>`) не подставляется;
- ★/✗ с родителем (reply на `qmat_*`) — это ОТВЕТ, а не отбор (решение
  Commander 12.10, [task:tb_1791843894_63972_1]): кто считает отборы оператора
  (ключевые кадры, selects, string-out), берёт только favorite/negative БЕЗ
  родителя. Проверено в коде: суммы (`pairInOutRanges`) — только in/out;
  XML-клипы — только in/out-пары, ответы едут в Premiere лишь цветными
   маркерами. Честно: Clear по видам бережёт и родителей вопросов, и ответы
   на них (reply на `qmat_*` — только поштучно, один клик в окне Markers;
   confirm пишет число пощажённых ответов; undo сессионный — после рестарта
   только переответ).
- `source.by` — имя агента (автор `agent:<имя>`, пометка «ИИ»).
- Дисциплина отдач: каждая ревизия агента — своя версионная подпапка
  `<имя>_vNN/`; старые ревизии не трогать и не перезаписывать.

## 5.2. Сверка людей — капча из слайдов (решение оператора 12.10)

Люди сверяются не видео с рамкой, а картинками: «тот же человек?» —
вопрос про лицо, не про время. Сцены и всё, где важно движение
(камера, заминки), — видеоопросом §5.1. Плееру новый режим не нужен:

- агент собирает ОДИН mp4 из слайдов (одна пара = один слайд, ~10 с)
  и к нему обычный вопрос-плейлист §5: запись = слайд, `in_sec`/`out_sec`
  = границы слайда, `label` «Same person?», `source.by` = `agent:<роль>`;
- человек отвечает карточкой: Confirm = один человек, Reject = разные,
  Not sure = не знаю; следующая пара — штатный In–Out Play;
- обрезки лиц режет агент локально, по проверенным боксам; кадры не
  покидают машину.

Требования к генератору слайдов — капча v2 (фидбек оператора по двум
прогонам people_captcha_v01, 12.10):

1. Слева сетка обрезков человека A, справа — B, сверху ID обоих.
   НОМЕР на КАЖДОМ обрезке (на квадрате, A1…An / B1…Bn) — чтобы
   в комментарии можно было сказать «A3 — не он».
2. Лица строго горизонтально по линии глаз. Вертикальные кадры
   доворачиваются ДО нарезки — и камерные вертикалки (rotation в
   метаданных), и айфон; лицо на слайде не лежит на боку и не завалено.
3. Обрезки крупнее, без пустот между ними; в нижней полосе слайда, где
   поверх кадра лежит таймлайн плеера, — ничего.
4. Фон ЧЁРНЫЙ (как тёмный интерфейс Premiere): белый фон глаз читает
   как материал.
5. Мало обрезков (1 с какой-то стороны) — честно: Not sure там нормальный
   ответ.

Карточка вопроса следует за playhead внутри одного mp4 (0.25.56) —
`question_id` ответа достоверен, сверять пару по нему.

## 6. Что НЕ входит (следующие задачи)

Проигрывание отбора подряд в плеере, монтажный лист, бриф-файл —
владельцы в протоколе §6. Reply-формат — §6.2, кнопка ответа ↳ в окне

## 6.1. Автор (работает с 0.25.31, [task:tb_1791583578_64923_1])

Агент подписывается сам 3-м сегментом / полем `author: "agent:<роль>"`
(это и есть пометка «ИИ», протокол §4 п.7); человек подписывается пассивно
именем macOS (окно Markers, поле + Save; при первом создании один раз
prompt поправить). Статусов open/done больше нет (убраны в 0.25.34,
задачи живут в таскборде); старые файлы со `status` читаются без ошибки
(поле игнорируется). Текст ровно с одним «|» внутри, где середина похожа
на имя, прочитается как автор (край парсера — принято).

## 6.2. Ответы (reply, работает с 0.25.32, [task:tb_1791585558_31907_1])

Ответ — ОТДЕЛЬНЫЙ комментарий в той же точке со своим автором.
Ссылка на родителя — `reply_to` = marker_id вопроса:

- sidecar/JSON: поле `reply_to: "q03-c1"` рядом с `author`;
- SRT: префикс текста `↳ q03-c1: <текст>` (старый плеер читает как обычный
  коммент — деградация, новый — как ответ);
- в окне Markers ответ — плоской строкой `↳ автор: текст` под родителем;
- в Premiere/XML/EDL — отдельным маркером с пометкой `↳` в имени
  (вложенности Premiere не умеет; в EDL пометка ASCII `>> `, глифы режутся —
  EDL строго ASCII).

## 7. Чтение из MCP-модуля

Файл — обычный markdown в репозитории, агент индексации
(cut-player-mcp, другой репозиторий) читает его напрямую из git.
Отдельный MCP-тул-указатель (`cut_player_read_manifest`) — follow-up
для Phi, здесь не делается.
