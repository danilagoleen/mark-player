# Манифест данных Mark Player для агента

Как агенту без GUI, одними файлами, положить ШТАТНЫЕ маркеры плеера
(in/out, комментарии) для видео — чтобы их увидели и плеер, и Premiere.

Протокол: этапы 6, 7, 11 — `docs/218_ph_CUT_CATALOG/CUT_PRODUCTION_PROTOCOL_2026-10-09.md`.
Живой манифест кнопок: `window.vetkaPlayerLab.manifest()` в запущенном плеере.

**Правило №1.** Агент сначала ищет готовый инструмент в этом документе.
Новый формат — только через Альфу: новое поле должны увидеть и плеер,
и Premiere (протокол §4 п.1).

## 0. Что такое штатные маркеры <!-- {#hpdm-s0} -->

Виды: `favorite` (★), `negative` (✗), `in` (⇒), `out` (←),
`comment` (·), `chat` (·). Пара `in` + `out` = скобки фрагмента, их сумму
считает плеер. Время — СЕКУНДЫ от начала файла (в SRT — `HH:MM:SS,mmm`).

Честно: плеер НЕ подбирает файлы-спутники сам при открытии видео.
Импорт — явный: меню File → Import или вызов `window.vetkaPlayerLab`
(см. §3). Файл, просто лежащий рядом с видео, маркеров не даст.

`manifest_version: 2`, [task:tb_1792532431_93509_9]) — здесь та же таблица
для чтения глазами (разведка `RECON_PLAYER_FOR_AGENT_2026-10-21.md` §2/§4).
Статус: **есть** — работает сейчас, **частично** — работает не в той форме,

## 1. Путь А: SRT-файл маркеров (самый простой)

Формат — тот же, что пишет сам плеер (Export → Current Video →
Subtitles (SRT)…): номер, время, строка `ГЛИФ label | text`.

```srt
1
00:00:12,500 --> 00:00:12,500
⇒ заминка 3

2
00:00:14,000 --> 00:00:18,000
· спорное место | проверить по расшифровке

3
00:00:18,000 --> 00:00:18,000
← заминка 3
```

Глифы: `★ favorite`, `✗ negative`, `⇒ in`, `← out`, `· comment/chat`.
Точечный маркер — нулевая длительность (`start == end`).
Импорт: File → Import → Subtitles (SRT)… (или
`vetkaPlayerLab.importSubtitlesText(text, mediaPath)`), затем подтвердить
«создать маркеры». Эвристика плеера: если ≥50% строк начинаются с глифа —
это SRT маркеров, а не субтитры (`looksLikeMarkers`). Кодировка: UTF-8,
иначе cp1251. Повторный импорт заменяет дорожку целиком.

## 2. Путь Б: Markers JSON / sidecar `.sos.json`

Sidecar (`sos_version: "0.3"`, пишет Export → Markers (JSON/SOS)…):

```json
{
  "sos_version": "0.3",
  "source": "cut_player",
  "media_path": "/idx/P1755050.mov",
  "content_hash": null,
  "generated_at": "2026-10-09T00:00:00.000Z",
  "markers": [
    { "marker_id": "q03-in", "kind": "in", "start_sec": 12.5,
      "end_sec": 12.5, "anchor_sec": 12.5, "label": "заминка 3", "text": "" },
    { "marker_id": "q03-c1", "kind": "comment", "start_sec": 14.0,
      "end_sec": 18.0, "anchor_sec": 16.0, "label": "спорное место",
      "text": "проверить по расшифровке" }
  ],
  "provisional_events": []
}
```

Импорт принимает и короткий массив `[{kind, text|label, anchor_sec|time,
start_sec, end_sec}]` — лишнее отбрасывается, неизвестный `kind` становится
`favorite` (`normalizeImportedMarker`). Импорт: File → Import →
Markers (JSON)…. Привязка к видео — по `media_path` (копия/переименование
находится по `content_hash`, `null` = хеш неизвестен, честно).

Точные имена файлов экспорта (UPD 13.10, [task:tb_1791907340_49359_1]):
Export → Current Video → Markers (JSON/SOS)… пишет `<имя>.sos.json`
(по имени текущего видео; `App.tsx:performExportJson`). Export → Playlist →
Markers (JSON/SOS)… пишет `<имя плейлиста>.markers.json`
(`App.tsx:3102`). Кнопка Export окна Playlist пишет `<имя>.json` + рядом
sibling `<имя>.json.answers.json` (с 0.25.74, [task:tb_1791885959_77379_1]).
`_export` в именах вроде `Orientation_check_v1_export.json` — НЕ суффикс
кода, а часть имени, которое дал плейлисту агент: код пишет
`<sanitized playlist name>.json` как есть.

## 3. Как плеер подхватит (без GUI — никак, нужен один шаг человека или API)

Варианты: (а) оператор открывает видео и жмёт File → Import → …;
(б) агент в десктопе вызывает `vetkaPlayerLab.importSubtitlesText(text,
mediaPath)` — `mediaPath` обязан совпадать с открытым файлом, иначе тост
«open a video first». После импорта маркеры — штатные: видны на шкале,
в окне Comments, едут в экспорт.

## 4. Как маркеры уходят в Premiere

- Timeline (XML)… — маркеры файла с цветами видов (comment/note/chat —
  синий, favorite — зелёный, negative — красный; ABGR, проверено глазами
  в Premiere 24.09). Частота кадров — честная (`resolveXmlFps`:
  container/probe/estimated/fallback — сверить настройки сиквенса).
- Markers (EDL, DaVinci)… — для DaVinci.
- Для плейлиста — те же пункты в Export → Playlist (пакет:
  XML + SRT + JSON + Review Notes + frames + `.editor/`).
- Сырые скобки вопроса (§5) в Premiere не уходят; штатные маркеры,
  записанные при импорте вопрос-плейлиста, уходят как обычно.

## 5. Плейлист-вопрос: импорт сразу пишет штатные маркеры <!-- {#hpdm-s5} --> (решение 10.10, работает с 0.25.34, [task:tb_1791654032_27281_1])

Агент отдаёт ОДИН JSON на все видео (`vetka.cut.question_playlist/1` —
схема в `QUESTION_PLAYLIST.md`): запись = путь + `question_id` + вопрос +
гипотеза + `in_sec`/`out_sec` + `markers`. Человек открывает файл в панели
Playlist — скобки записей СРАЗУ становятся штатными маркерами, без кнопок
и подтверждений (файл агента и есть подтверждение). `source.by` — имя
агента (станет автором `agent:<имя>`); без него автор — `agent:agent`:

- `in_sec` / `out_sec` → пара `in` + `out` (в XML режут клипы, как ручные I/O);
- `markers` записи → комменты (`label` = вопрос, `text` = гипотеза + текст);
- автор всех — `agent:<роль>` из `source.by` (это и есть пометка «ИИ»);
- повторный импорт дублей не плодит (детерминированные id `qmat_<qid>_*`).

Эфемерных скобок больше нет: пунктира, скип-движка и кнопки
«Материализовать» (0.25.33) — тоже. Дальше всё штатно: окно Markers,
ответы кнопкой ↳, Export → Playlist → XML (подрезанные клипы
с комментариями в Premiere).

Правило резолва путей: плеер открывает `entry.path` как есть, без подмен
(прокси не конформит в исходник и наоборот). Коллизия имён (у прокси
и исходников одинаковые basenames) — на совести агента: клади точный путь.

Две «скобки» (не путать):

1. In–Out Play (ножницы) — РЕЖИМ просмотра: играть только внутри скобок.
2. Штатные `in` / `out` (⇒/← — ставит человек клавишами I/O или агент
   в SRT) — ДАННЫЕ: в XML становятся разрезами клипов.

## 5.1. Калибровка сцен для Беты (решение 11.10): новый плейлист штатными инструментами

Старые `camera_calibration.json` / `scene_proposals.json` — не плейлисты,
больше не отдавать (плеер 0.25.45 ел их transitional-мостом — мост остаётся
для чтения, новым форматом не является). Новый лист калибровки сцен —
обычный вопрос-плейлист §5 (`vetka.cut.question_playlist/1`), собранный
только штатными средствами:

- запись = файл; `in_sec` / `out_sec` — штатные скобки (I/O или числа —
  в XML режут как ручные);
- ВСЕ вопросы — в поле `question` + штатными комментариями (`markers`
  записи: `label` = вопрос, `text` = гипотеза); survey-форматов не лепить —
  запрещено. Разрешённые штатные поля (с 0.25.52): `bbox` / `bbox_end` (см.
  ниже) и `label` ≤ 80 символов (длиннее плеер режет сам; имя маркера
  в Premiere обрезается на полуслове — держи коротким);
- регион-лицо: `bbox: {x, y, w, h}` в ДОЛЯХ кадра (x,y — левый верхний
  угол; всё 0..1, x+w ≤ 1, y+h ≤ 1), опционально `bbox_end` — рамка на
  `out_sec`. Канон — поля ЗАПИСИ; `bbox` внутри `markers[i]` tolerated
  (плеер подхватит из первого маркера, где есть — так лёг people_merges_v01).
  Плеер рисует рамку поверх кадра, пока активен вопрос, и
  линейно едет `bbox` → `bbox_end` за `in..out` (на тугих скобках выглядит
  как трекинг). Мусор (вне 0..1, нулевой размер, вылезание за кадр)
  отбрасывается целиком — лучше без рамки, чем мимо лица. Честно:
  в Premiere рамка уезжает ТЕКСТОМ (`[region …]` в тексте in/out-маркера —
  в XMEML/EDL/SRT полей под геометрию нет);
- подпись поверх кадра: необязательное поле записи `caption` (строка).
  Плеер показывает её поверх кадра, пока плейхед внутри `in_sec`..`out_sec`
  записи, и прячет вне окна. Это НЕ SRT-дорожка и НЕ маркер-комментарий:
  в SRT-маркеры не подмешивается, в Premiere не уезжает (§5.6);
- вопросы и ответы живут в окне Comments. **Одна правда — маркеры**
  (решение 12.10, плеер 0.25.55, [task:tb_1791809796_24701_1]): ответ
  человека — reply-маркер на маркер вопроса `qmat_*` (кнопка карточки
  Confirm / Reject / Not sure пишет `[answer] choice: comment (verdict)`,
  свободный текст ↳ — тоже ответ, verdict `comment`). `answers.json` —
  НЕ второй писатель, а выжимка `answersFromMarkers` из маркеров: плеер
  пересобирает её при каждом ответе (имя — от пути плейлиста; без пути —
  запасной аутбокс). Поля выжимки берутся из маркеров: `t_sec` = точка
  ответа, `answered_at` = время создания ответа, `in_sec`/`out_sec` =
  текущие скобки вопроса (человек двигает их сам). Маркер вопроса несёт
  `question_id` полем. В выжимку идут только прямые ответы на `qmat_*`;
  треды на обычных маркерах — просто комментарии. Автор ответа на вопрос
  агента — отвечающий; автор вопроса (`agent:<роль>`) не подставляется;
- три места, где лежат ответы оператора (UPD 13.10,
  [task:tb_1791907340_49359_1]): (1) reply-маркеры (`author` +
  `reply_to: qmat_<qid>_*`, формат — §6.2); (2) `<плейлист>.answers.json`
  рядом с плейлистом (+ sibling при экспорте окна); (3) запасной аутбокс
  (`vetka_player_lab_question_answers_outbox_v1` — веб/без пути). Агент
  читает (2), при отсутствии — (3); (1) — первоисточник, из него плеер
  пересобирает (2) при каждом ответе.
- ★/✗ с родителем (reply на `qmat_*`) — это ОТВЕТ, а не отбор (решение
  Commander 12.10, [task:tb_1791843894_63972_1]): кто считает отборы оператора
  (ключевые кадры, selects, string-out), берёт только favorite/negative БЕЗ
  родителя. Проверено в коде: суммы (`pairInOutRanges`) — только in/out;
  XML-клипы — только in/out-пары, ответы едут в Premiere лишь цветными
   маркерами. Честно: Clear по видам бережёт и родителей вопросов, и ответы
   на них (reply на `qmat_*` — только поштучно, один клик в окне Markers;
   confirm пишет число пощажённых ответов; undo сессионный — после рестарта
   только переответ).
- `source.by` — имя агента (автор `agent:<имя>`, пометка «ИИ»).
- Дисциплина отдач: каждая ревизия агента — своя версионная подпапка
  `<имя>_vNN/`; старые ревизии не трогать и не перезаписывать.

## 5.2. Сверка людей <!-- {#hpdm-s52} --> — капча плейлистом по Proxies/ (решение оператора 13.10, протокол §4 п.13)

Люди сверяются не видео с рамкой, а картинками: «тот же человек?» —
вопрос про лицо, не про время. Сцены и всё, где важно движение
(камера, заминки), — видеоопросом §5.1. Плееру новый режим не нужен:

- агент отдаёт обычный вопрос-плейлист §5 по `Proxies/`: запись = отрезок
  клипа, `in_sec`/`out_sec` = границы, `label` «Same person?»,
  `source.by` = `agent:<роль>`; вертикали — предповёрнутыми клипами
  (плеер не поворачивает, rotate только в CUT player); без вшитого текста;
- человек отвечает карточкой: Confirm = один человек, Reject = разные,
  Not sure = не знаю; следующая пара — штатный In–Out Play;
- обрезки лиц режет агент локально, по проверенным боксам; кадры не
  покидают машину.
- куда что класть (протокол §4 п.12–13): человеку — только `edit/calibration/`
  (то, что открывается в плеере); входы, ключи и разметка агента — `phi_runs/`.
  Капчи «20–25 вопросов вслепую» больше нет (слово оператора 13.10, протокол
  §4 п.3): калибрующий агент смотрит кадры и размечает сам, человеку — только
  спорное, по 1–3 вопроса за раз.

Требования к генератору слайдов — капча v2 (фидбек оператора по двум
прогонам people_captcha_v01, 12.10):

1. Слева сетка обрезков человека A, справа — B, сверху ID обоих.
   НОМЕР на КАЖДОМ обрезке (на квадрате, A1…An / B1…Bn) — чтобы
   в комментарии можно было сказать «A3 — не он».
2. Лица строго горизонтально по линии глаз. Вертикальные кадры
   доворачиваются ДО нарезки — и камерные вертикалки (rotation в
   метаданных), и айфон; лицо на слайде не лежит на боку и не завалено.
3. Обрезки крупнее, без пустот между ними; в нижней полосе слайда, где
   поверх кадра лежит таймлайн плеера, — ничего.
4. Фон ЧЁРНЫЙ (как тёмный интерфейс Premiere): белый фон глаз читает
   как материал.
5. Мало обрезков (1 с какой-то стороны) — честно: Not sure там нормальный
   ответ.

Карточка вопроса следует за playhead и переключается при смене записи
(0.25.56, 0.25.70) — `question_id` ответа достоверен, сверять пару по нему.

## 5.3. Индексные файлы, которые плеер НЕ читает (UPD 13.10, [task:tb_1791907340_49359_1])

Честно: ниже — формат стороны индекса (cut-player-mcp), не плеера.
Mark Player эти файлы не открывает и не парсит (проверено `rg` по `src/` —
ноль упоминаний). CUT-направлению они нужны (протокол §4 п.15), поэтому
описаны здесь, а не в коде плеера:

- `orientation.json`: `content_rotation_cw`, `segments` (отрезки поворота),
  `evidence.source` (`operator` | `visual_review` | `faces`) + `previous`,
  защита ручного поворота `kept: operator` (код — `orientation.py`:
  `normalize_segments`, `rotation_at(t)`, `kept_operator`). Кадр берётся стоя:
  `orientation.rotation_at(t)`. Поворот в Mark Player НЕ делать (протокол §6,
  слово оператора 13.10) — вертикали отдавать предповёрнутыми клипами (§5.2).
- `key_person` (поле `framing.json` на каждый план; по нему мерится крупность;
  канон-карта §3.9, UPD 13.10 вечер): `face` — главный найден по лицу (мерить
  по канону R0 в высотах головы); `body` — лица нет, но есть скелет rtmo
  (мерить по нижней видимой точке тела); `none` — людей нет (`macro` либо
  `scale=null, reason=no_person`). Шкала крупности — §3.9.1 (Кулешов +
  голливудские алиасы, EN-код в сайдкар).

## 5.4. Отчёт о показе `<плейлист>.session.json` <!-- {#hpdm-s54} -->

Плеер сам пишет соседний файл `<плейлист>.session.json` — где человек
остановился и что успел отметить ([task:tb_1792532431_93509_9], контракт
разведки §5). `.session.json` — не `answers.json`: `answers.json` это
выжимка ответов (§5.1), а отчёт показывает состояние показа и на вопросы
не отвечает; второй писатель в `answers.json` не появляется.

```json
{
  "session_version": 1,
  "playlist": "/idx/reel_candidates_v03.json",
  "started_at": "2026-10-21T09:12:03.120Z",
  "updated_at": "2026-10-21T09:19:44.010Z",
  "entry_index": 1,
  "question_id": "q07",
  "path": "/Volumes/tempwork/a/P1755051.MOV",
  "t_sec": 812.4,

```

- `session_version` — сейчас `1`; поле обязательно, чужая версия = не читать.

## 5.5. Очередь команд агента: `inbox/` + `ack/` <!-- {#hpdm-s55} -->

С шага 2 ([task:tb_1792536109_79489_5], разведка §6 п.2) агент управляет
показом **файлами**, без порта и сетевой поверхности. Плеер опрашивает
`inbox/` раз в 0,5 с; каждый файл получает ack.

**Где лежит** (`app_data_dir`, macOS) — `~/Library/Application Support/ai.vetka.playerlab/`:

```
inbox/      <id>.cmd.json      ← агент кладёт команду
ack/        <id>.ack.json      ← плеер пишет ответ (по одному на команду)
inbox/done/ <id>.cmd.json      ← исполненные/отвергнутые (аудит, плеер переносит сам)
playlists/  queue_<id>.playlist.json ← inline-подборка из команды open_playlist
```

Точные пути печатает сам плеер: `invoke("command_queue_info")` возвращает
`root/inbox/ack/playlists/done` (для внешнего агента корень — `app_data_dir`
по identifier `ai.vetka.playerlab`; руками путь не угадывать).

**Команда** `<id>.cmd.json` (`id` = имя файла без суффикса, `[A-Za-z0-9._-]`):

```json
{
  "cmd_version": 1,
  "id": "c0ffee-1",
  "verb": "open_playlist",
  "args": {
    "name": "Спорные заминки",
    "by": "Beta",
    "task": "tb_...",
    "entries": [
      { "path": "/Volumes/tempwork/.../Proxies/P1755050.mov",
        "question_id": "q07", "question": "Один ли человек?",
        "hypothesis": "склейка двух людей",
        "in_sec": 812.4, "out_sec": 819.0,
        "choices": ["confirm", "reject", "not_sure"],
        "markers": [{ "kind": "comment", "t_sec": 815.0,
                      "text": "агент: похоже на склейку" }] }
    ]
  },
  "created_at": "2026-10-21T20:00:00Z",
  "expires_at": "2026-10-21T20:10:00Z",
  "author": "Beta"
}
```

- Глаголы: `open_playlist`, `open_file`, `seek`, `play_range`, `next`, `pause`.
- `open_playlist` берёт `args.path` **или** `args.entries[]` (подборка/форма
  вопроса). Inline-записи плеер сохраняет в `playlists/queue_<id>.playlist.json`
  и открывает как обычный вопрос-плейлист — `in`/`out` становятся штатными
  маркерами, ответы ложатся в `<плейлист>.answers.json`, отчёт — в `.session.json`.
- **Комментарии агента** — штатные маркеры в `entries[].markers[]`
  (`kind: "comment"`, `text`), автор берётся из `args.by`/`author`
  (`agent:<кто>`). Своих полей не заводить (§5.1).
- `expires_at` — ISO-8601 UTC; просроченная команда не исполняется.
- Пути: только `$HOME`, `/Volumes`, `$TEMP`, файл обязан существовать
  (canonicalize; те же корни, что у loopback-медиа). Иначе — ack `error`.
- Идемпотентность: команда с уже существующим ack не исполняется второй раз.
  Пока ack нет, плеер повторяет событие (at-least-once) — первый может обогнать
  подписку окна; повтор после падения безопасен, глагол не исполнится дважды.

**Ответ** `ack/<id>.ack.json`:

```json
{ "ack_version": 1, "id": "c0ffee-1", "verb": "open_playlist",
  "status": "done", "at": "2026-10-21T20:00:00.800Z" }
```

`status`: `done` | `error` | `expired`. У `error` есть `error: {code, message}`.
Коды: `invalid_json`, `invalid_command`, `unsupported_version`, `invalid_id`,
`unknown_verb`, `invalid_args`, `invalid_expires_at`, `path_not_found`,
`path_not_file`, `path_forbidden`, `expired`, `execution_failed`.

### 5.5.1. Ответы оператора: `answers.json` → `ack/<cmd>.answers.json`

С 22.10 ([task:tb_1792634443_73606_2], контракт Commander) источник истины
для агента — sibling **`<плейлист>.json.answers.json`**, а НЕ `session.json`
(session — состояние UI, на него не опираться). Документ всегда несёт
прогресс; `answers` внутри — только ответы на `question_id` этого плейлиста:

```json
{
  "answers_version": 2,
  "playlist_id": "queue_c0ffee-1",
  "question_ids": ["q07", "q08"],
  "answered_question_ids": ["q07"],
  "pending_question_ids": ["q08"],
  "complete": false,
  "updated_at": "2026-10-21T20:03:00Z",
  "answers": [ { "question_id": "q07", "verdict": "favorite", "...": "..." } ]
}
```

- При открытии плейлиста плеер пересобирает документ: чужие ответы
  отбрасываются, исходник один раз сохраняется рядом как
  `<answers>.bak` (файлы-улики не теряются). Пустой плейлист без ответов
  всё равно получает документ с `pending_question_ids` — агенту видно,
  что ждём оператора.
- **Сигнал** — когда `complete` становится `true`, плеер пишет копию
  документа в `ack/<cmd>.answers.json` с `"sent_by": "auto"`. Оператор
  может отправить и неполные ответы кнопкой **Send to agent** в карточке
  вопроса — `"sent_by": "operator"`. `<cmd>` — id команды `open_playlist`;
  для плейлиста, открытого вручную, — `playlist_id` без префикса `queue_`.
  Этот файл не затирает `<cmd>.ack.json` глагола.
- Агент поллит `ack/` и читает `answers.json`/`ack/<cmd>.answers.json`;
  поллинг `session.json` не нужен.
- UI: на файле с несколькими вопросами карточка показывает
  «Question 1/2 on this file · answered» и кнопку перехода к следующему
  неотвеченному — второй вопрос не теряется.

## 5.6. Подпись поверх кадра: поле `caption` <!-- {#hpdm-s56} -->

Шаг 3 ([task:tb_1792547382_5133_1], разведка §2 «Подпись/титр поверх
кадра», протокол §6). Агенту нужно не только показать момент, но и
подписать его словами — коротким титром поверх кадра.

```json
{ "path": "/Volumes/tempwork/.../Proxies/P1755050.mov",
  "question_id": "q07",
  "in_sec": 812.4, "out_sec": 819.0,
  "caption": "вход в кадр — проверить склейку" }
```

- `caption` — необязательная **строка записи** (`QuestionEntryFields`),
  рядом с `question`/`in_sec`/`out_sec`. Пустая строка и не-строка
  отбрасываются при нормализации; старый плейлист без `caption` читается
  как раньше.
- Показ: поверх кадра, пока плейхед внутри `in_sec`..`out_sec` активной
  записи (`out_sec` нет — до конца файла). Вне окна подпись скрыта.
  Переключатель Subtitle Show её не выключает: это данные агента, а не
  дорожка субтитров. Если у файла есть и SRT-реплика, и `caption`, видны обе.
- Границы честные: **в Premiere `caption` не уезжает** — в XMEML/EDL/SRT
  нет поля под текстовую подпись; в SRT-маркеры её не подмешиваем, иначе
  чужой плеер прочитает подпись как комментарий-маркер. Кто хочет титр в
  монтаже — делает его в Premiere по этой подписи.
- Транспорт — `file`: подпись едет в `<плейлист>.json` (и в inline-подборке
  из очереди §5.5 — незнакомые поля записи сохраняются).

## 5.7. Палитра/обмен с индекс-модулем <!-- {#hpdm-s57} -->

UPD 21.10 ([task:tb_1792598687_4475_1]). Владелец отбора, `cut.db` и
экспорта — индекс-модуль `cut-player-mcp`; плеер — показ, маркеры и
ответы человека. Палитра — **необязательный** этап: контракт ниже один
для любой подборки, палитра лишь один из её видов.

Транспорт — файлы/CLI, не MCP и не сеть:
`cut_player_playlist` (модуль → `playlist.json`), `cut_player_export_xml`
(модуль → XMEML), `cut_player_import_answers` (ответы плеера → база).
Плеер читает только `playlist.json` схемы `vetka.cut.question_playlist/1`
(§5); `palette.json` он **не парсит** — это модульный дескриптор.

### Контракт

Обе стороны пишут в артефактах одно и то же:

```json
{
  "contract_version": "1",
  "playlist_schema": "vetka.cut.question_playlist/1",
  "db_version": 9,
  "index_fingerprint": "people/phase.json#<hash>",
  "fps": 25
}
```

`fps` — из индекса/контейнера, не выдуманный: от него считаются кадры
in/out и маркеров. `index_fingerprint` связывает плейлист с версией
индекса, из которой он собран.

### `palette.json` — дескриптор модуля

```json
{
  "items": [
    { "id": "it_0001",
      "ref": { "media": "P1755160.MOV", "in_sec": 26.0, "out_sec": 38.0,
               "person_id": "P112", "phase": "after",
               "phase_piece": [25.75, 48.5] },
      "fav": true, "title": "P112 героиня — готовая укладка" }
  ],
  "bblocks": [
    { "label": "G6d У зеркала — ПОСЛЕ",
      "item_ids": ["it_0001"], "in_sec": 0.0, "out_sec": 12.0 }
  ]
}
```

- `items[].id` — детерминированный от `ref` (тот же ref при пересборке
  даёт тот же id), поэтому ответы и правки переживают пересборку.
- `ref` — **один** объект: `media` — basename исходника, `in_sec`/`out_sec` —
  секунды файла, `person_id`/`phase`/`phase_piece` обязательны,
  `phase_piece` — `[start, end]` секунды файла.
- `fav` — ★, `title` — человеческая подпись; **ни то, ни другое не едет
  в имя клипа**.
- `bblocks[]` — блоки показа: `item_ids` — массив `items[].id` (не refs и
  не объекты), `in_sec`/`out_sec` — координаты таймлайна модуля.

Инвариант блока:

```
b.in_sec == timeline_start(first_item)
         == сумма длительностей предыдущих items + 20 * (число блоков до него)
```

Блок обязан начинаться на границе item. Полный `b.in_sec..b.out_sec` —
только **sequence-маркер** в XMEML; в плеер уезжает точка, не диапазон.
Генератор модуля проверяет инвариант и падает на битом дескрипторе, а не
чинит его пересчётом.

### Маппинг в `question_playlist/1`

| Палитра | Запись плейлиста |
|---|---|
| `ref.media` + исходник | `path` — абсолютный путь, `name` = **basename** |
| `ref.in_sec` / `ref.out_sec` | `in_sec` / `out_sec` (секунды файла) |
| `items[].id` | `question_id` |
| `ref` | `ref = { layer: "palette", id, person_id, phase, phase_piece }` |
| `fav: true` | marker `favorite` на `ref.in_sec` |
| `title` | marker `comment`, `text = title`, на `ref.in_sec` |
| `bblocks[]` | marker `comment`, `text = label`, ровно на `first_item.ref.in_sec` |

**Канон имени (21.10, Beta):** `name` = basename исходника **везде** — в
`entry.name`, в `clipitem/name` и в проекции P. `title` не подменяет имя:
он едет comment-маркером в той же точке, что ★. Так держится правило
оператора «клипы не переименовывать, все пометки — в маркерах»: монтажёр
перелинковывает по именам файлов.

`cut_player_export_xml` (модуль) умеет больше плеера: несколько файлов,
маркеры клипов, ★, блоки **полнодлинными** sequence-маркерами,
Basic Motion (поворот), `name = basename`.

### Ответы

Плеер пишет `<плейлист>.answers.json` и `<плейлист>.session.json` в своей
форме: `question_id`, `verdict`/`choice`/`comment`, `confirmed_by`,
`t_sec`, `in_sec`/`out_sec`. `ref`/`person_id` в ответы **не добавляем** —
это дело модуля: `cut_player_import_answers(playlist, answers)` резолвит
`question_id → ref/person_id/phase`. `t_sec` — секунды файла; таймкод
отвергается. Неизвестный `question_id` или несовпавший `ref` — ошибка
импорта, а не «примерно тот же» момент.

### Проекция P (conformance)

> **P = XMEML без таймлайновых координат и без фильтров; сравниваются
> файловые in/out, имена, маркеры, ★ и порядок.**

P сравнивает: порядок clipitem, `name` = basename, файловые `in`/`out`,
маркеры (`name`, `comment`, `in`, `out`, цвет ★), `question_id`/`ref` в
плейлисте. P **не** сравнивает: `clip <start>/<end>`, `sequence
<duration>`, sequence-маркеры блоков, `<filter>`/Basic Motion. Поэтому
20-секундные паузы модуля и их отсутствие у плеера на P не влияют —
пересчитывать таймлайн не нужно.

### Фикстура и тест

`player_playground/tests/conformance/palette_v01/`:

| Файл | Что это |
|---|---|

`src/lib/paletteConformance.test.ts` строит вход экспортёра из

Полный гейт модуля — `expected.module.xml` (с блоками и Basic Motion),
`expected.answers.json`, `expected_decisions.json` — живёт в фикстуре

- не ставит полнодлинные блок-маркеры: маркер записи — точка `t_sec`;
- не заводит сетевой транспорт — только файлы/CLI.
